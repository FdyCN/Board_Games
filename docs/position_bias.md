# 位置偏差 (Position Bias) 问题说明

## 问题描述

在自对弈训练过程中观察到，玩家位置 3（最后一位玩家）的胜率显著高于其他位置，且随训练迭代增加而上升。

**训练日志示例（第 25 次迭代）：**
```
胜率分布: [玩家 0: 15.62%, 玩家 1: 18.75%, 玩家 2: 12.50%, 玩家 3: 34.38%]
```

这种现象可能有两个原因：

### 1. 游戏固有优势（正常现象）

某些游戏在设计上，特定位置具有策略优势：
- **先手优势**：如国际象棋，先手玩家胜率约 52-55%
- **后手优势**：如 Splendor，后手玩家可以看到其他玩家的策略后做出反应

**判断标准**：
- 胜率差异 <15%：可能是游戏设计导致
- 各位置胜率相对稳定，不随训练变化太大

### 2. 模型过拟合到特定位置（问题）

模型学习了位置相关的策略，而非通用的游戏策略：
- 模型在特定位置表现好，但在其他位置表现差
- 无法泛化到不同的游戏场景

**判断标准**：
- 胜率差异 >20%：很可能是过拟合
- 特定位置胜率随训练增加而持续上升，其他位置下降

## 根本原因分析

查看 `games/splendor/encoder.py:165-168`：

```python
# 当前玩家 ID (4) - one-hot
obs[idx : idx + 4] = 0
obs[idx + state.current_player] = 1.0
```

**编码器包含位置信息：**
1. 观察从特定玩家视角编码（第一人称）
2. 同时编码当前轮到哪个玩家行动
3. 模型可以通过回合顺序推断自己的绝对位置
4. 模型可能学习到"我在位置 3 时，应该使用策略 X"

## 位置信息的利弊

### 利（保留位置信息）：
- **游戏策略需要**：在 Splendor 中，知道自己的回合顺序对制定策略很重要
- **真实信息**：真实玩家也知道自己的位置
- **某些游戏必需**：如扑克，位置是核心战略要素

### 弊（移除位置信息）：
- **更通用策略**：模型学习与位置无关的游戏原理
- **更好泛化**：可以应对任何位置
- **避免过拟合**：防止模型依赖位置特征而非游戏理解

## 测试方法

使用 `scripts/test_position_bias.py` 测试模型在各位置的表现：

```bash
python scripts/test_position_bias.py \
    --checkpoint checkpoints/checkpoint_iter_100.pt \
    --num-games 100 \
    --device cpu
```

**测试原理：**
- 将训练好的模型放在位置 0, 1, 2, 3
- 其他位置使用随机 agent
- 测量每个位置对抗随机 agent 的胜率
- 计算胜率方差和范围

**期望结果：**
- ✅ **低偏差** (<10% 差异)：模型在各位置表现均衡
- ⚠️ **中等偏差** (10-20% 差异)：可能存在轻微过拟合
- ❌ **高偏差** (>20% 差异)：模型明显过拟合到特定位置

## 解决方案

### 方案 1：数据增强（推荐，简单有效）

在训练时随机旋转玩家位置：

```python
def rotate_observation(obs, state, original_player, new_player):
    """将观察从 original_player 视角转换为 new_player 视角"""
    # 重新编码观察，交换玩家顺序
    # ...
```

**优点**：
- 不改变游戏机制
- 增加训练数据多样性
- 模型被迫学习位置不变的策略

**实现**：修改 `training/experience.py` 添加旋转功能

### 方案 2：移除位置信息

修改 `games/splendor/encoder.py:165-168`：

```python
# 方案 A: 完全移除
# obs[idx : idx + 4] = 0  # 不编码当前玩家

# 方案 B: 只编码"是否轮到我"（相对位置）
obs[idx] = 1.0 if state.current_player == player_id else 0.0
obs[idx + 1 : idx + 4] = 0
```

**优点**：
- 强制模型学习位置无关策略
- 减少观察维度

**缺点**：
- 可能丢失有用的战略信息
- 对某些游戏（如扑克）不适用

### 方案 3：位置归一化训练

在自对弈时确保各位置训练数据均衡：

```python
# 每个 episode 随机决定哪个模型实例在哪个位置
# 而非始终让同一个模型在固定位置
```

**优点**：
- 保留所有游戏信息
- 自然地平衡位置经验

**缺点**：
- 实现较复杂
- 训练可能变慢

## 当前建议

基于您的观察（位置 3 胜率 34.38% vs 位置 2 的 12.50%），**差异超过 20%**，建议：

1. **立即测试**：运行 `test_position_bias.py` 量化偏差程度
2. **分析原因**：
   - 如果是游戏设计导致：可以接受
   - 如果是模型过拟合：需要修复
3. **根据测试结果选择方案**：
   - 偏差 <15%：无需修改，继续训练
   - 偏差 15-25%：考虑方案 1（数据增强）
   - 偏差 >25%：考虑方案 2（移除位置信息）

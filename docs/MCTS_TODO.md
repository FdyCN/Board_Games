## ⚠️ 已知问题 (不影响使用,但可以改进)

### 1. 动作索引映射 (优先级: 中)

**问题描述:**
- 当前系统中存在两种索引概念:
  - **相对索引**: 动作在 `legal_actions` 列表中的位置 (0, 1, 2, ...)
  - **全局索引**: 动作在 `action_space_size` 中的位置

- `action_to_index(action, legal_actions)` 返回的是相对索引
- 神经网络输出的是全局 action_space 的概率分布
- MCTS 需要将二者正确映射

**当前解决方案:**
- 在 `_get_policy_probs()` 中使用 `legal_mask` 提取非零概率
- 这种方法**假设 legal_mask 的顺序与 legal_actions 一致**
- 单元测试通过,说明当前实现可用

**潜在改进:**
- 重构游戏接口,统一使用全局索引
- 或添加 `action_to_global_index()` 方法明确映射关系

**影响范围:** 低 (当前实现已可用)

### 2. 多进程支持 (优先级: 高)

**问题描述:**
- MCTS 数据收集目前只支持单进程 (`num_workers: 1`)
- 原因: MCTS 搜索需要 `deepcopy(state)`,在多进程间传递会有序列化问题

**当前限制:**
```yaml
training:
  num_workers: 1  # 必须设为 1
```

**潜在解决方案:**
1. **Virtual Loss** - 允许多线程共享MCTS搜索树
2. **状态序列化优化** - 实现高效的状态克隆
3. **分布式MCTS** - 每个worker独立搜索,合并结果

**预期收益:** 训练速度提升 2-4 倍

---

### 3. GPU 批量推理优化 (优先级: 中)

**问题描述:**
- MCTS 每次模拟都单独调用神经网络 (batch_size=1)
- GPU 利用率低

**当前实现:**
```python
# 每次 MCTS 模拟都是单个状态
obs_tensor = torch.FloatTensor(obs).unsqueeze(0)  # (1, obs_dim)
action_probs = model.get_action_probs(obs_tensor)
```

**潜在优化:**
- **Batch MCTS**: 收集多个叶节点,批量评估
- **Virtual Loss**: 允许并行扩展多个节点
- 参考 AlphaZero 的实现

**预期收益:** GPU 训练速度提升 2-3 倍

### 4. MCTS 搜索树复用 (优先级: 低)

**问题描述:**
- 每次 MCTS 搜索都从头开始构建搜索树
- 同一局游戏中的连续搜索可以复用部分树结构

**当前实现:**
```python
# 每步都创建新的根节点
root = MCTSNode(state=state)
```

**潜在优化:**
- 保留上一步的搜索树
- 将新的根节点设为上一步选择的子节点
- 参考 AlphaZero 的"树复用"技术

**预期收益:** 搜索效率提升 10-20%

---

### 5. 终局价值估计 (优先级: 低)

**问题描述:**
- `_get_terminal_value()` 只返回 +1/-1/0 (胜/负/平)
- Splendor 是多人游戏,不是严格零和

**当前实现:**
```python
def _get_terminal_value(self, terminal_state, root_state) -> float:
    results = self.game.get_result(terminal_state)
    root_player = self.game.get_current_player(root_state)

    if results[root_player] > 0.5:
        return 1.0   # 胜利
    else:
        return -1.0  # 失败
```

**潜在改进:**
- 考虑排名 (第1名 +1, 第2名 +0.5, 第3名 -0.5, 第4名 -1)
- 考虑分数差距

**影响范围:** 低 (当前实现已足够)

---

### 6. MCTS 搜索深度限制 (优先级: 低)

**问题描述:**
- 当前 MCTS 会一直搜索到终局
- 对于长局游戏可能导致搜索树过深

**当前实现:**
- 没有深度限制,依赖终局检测

**潜在改进:**
- 添加 `max_depth` 参数
- 超过深度时使用价值网络估计

---

### 7. Dirichlet 噪声参数自适应 (优先级: 低)

**问题描述:**
- 当前 Dirichlet 参数固定: `alpha=0.3, epsilon=0.25`
- 不同游戏阶段可能需要不同的探索程度

**潜在改进:**
- 训练初期: 更大的噪声 (epsilon=0.5)
- 训练后期: 更小的噪声 (epsilon=0.1)
- 根据迭代次数自动调整
